# Cinematic Exposure

本版将暗房的新取放节奏应用于相机：直接拿取、从机身旁边短程安装，放置完成后再接受下一步操作；相机也稍微拿远。保留既有闪烁修正与暗房胶卷落下后显示预览的行为。

Minecraft 1.21.1 / NeoForge 独立附属。**v0.2.13-alpha 调整相机取放方式与持握距离。尚未进行游戏内测试。**

依赖 Java 21、NeoForge 21.1.255、Cinematic Interactions 0.18.12、Exposure 1.9.19。依赖不打包。

## 暗房

待冲印的选中帧以负片显示；实际冲印时按 Exposure 客户端菜单同步的进度，平滑混合成原始成片。复用 Exposure 的只读 NEGATIVE 图像效果与原图像渲染器，不修改保存的照片数据、比例、冲印时长或材料消耗，也不按动画帧创建贴图。纸底和边框始终可见。完成后，只要输出槽的照片、照片堆或混色相纸含当前帧，预览保持成片；取走匹配成品或切换到未冲印帧后显示负片。取消且没有匹配成品时恢复负片。没有胶卷时仍可显示输出槽顶部成片。

过渡进度只在本机打开对应原菜单/沉浸场景时持续同步；旁观者与退出场景后根据真实胶卷和成品数据显示负片或成片，不另建计时器或同步包。创造模式瞬时冲印直接显示结果。混色相纸预览表现当前帧的显影，不替代 Exposure 的最终多层合成。

Lightroom 使用 Cinematic 正式 `AddonStations` / `AddonScenes` / `AddonMenuStation` API，参照宿主 SmithingStation 和官方附属示例：由宿主处理走近工作台、抵达后俯身、相机与双手过渡、库存抽屉、退出及服务器会话。镜头目标为台面前方 0.70 格、上方 0.62 格，俯角 40°；不再受旧独立适配器的 0.35 格位移限制。

从宿主库存抽屉选择物品，再点击台面标注的胶卷、相纸、染料位置放入；点击成品拿取照片。台面后排提供冲印、上一帧、下一帧、工艺切换。当前工艺显示“常规／混色”；只有 Exposure 判定为折射状态时可切换，否则显示禁用原因。Shift 点击冲印使用 Exposure 原有创造冲印请求，权限和材料仍由 Exposure 校验。照片预览使用 Exposure 原有图像系统，平放在方块中央，保留宽高比、图像内容与贴图效果，随方块朝向旋转。可点击中央照片区域发起冲印，也可点击台面后排的冲印控制。预览存在时，双手在照片两侧工作；不再显示图片下方的闪烁条。

静置物品由独立 `LightroomRenderer` 方块实体渲染器绘制，读取 Exposure 已同步的实际库存。关闭场景、重进区块和重新接近时仍可显示；物品取走或方块移除后不保留副本。不生成掉落物实体、不另存库存、不新增网络包。中央是胶卷选中帧的预览；没有胶卷时可展示成品堆顶部照片，成品槽仍位于右侧。关闭暗房模块也会关闭这些附属渲染。

普通拿取胶卷、相纸、颜料或成品时，立即更新 Exposure 原手持物；Shift 取出直接进入库存。删除暗房额外的取出、下探口袋与两手递送时间线。普通持物使用 Cinematic 原 `Hands.follow` 的光标跟随、左右手选择、缓冲与轻点反馈，库存抽屉的光标物品也由原 SceneScreen 绘制。两手仍受肩部 0.74 格可达距离限制；后排按钮的手位留在照片附近。

放置沿用合成台 `layHands` 的短动作思路，基础时长 0.36 秒：Shift 放料从靠近玩家的台边取料，移到目标上方，放下后抬手；已在手上的物品从当前手位直接放入。放置对象和数量取自原菜单的真实变化，整组材料搬运一次。抽屉 Shift 委托一次原菜单 QUICK_MOVE，不另发宿主 QUICK 请求，不复制物品或配方逻辑。

**放置动作完成前不接受下一次台面、冲印或库存操作**，包括抽屉点击、Shift、数字键换槽和丢弃键。忙碌期间的点击直接忽略，不排队补发；按钮文字暂时变灰。Esc/走开仍能退出，服务端同步照常接收；纠正、退出或不可达超时会解除本次视觉状态。

台面静置物与手持物在实际落手时交接；新胶卷的预览也使用这一时机，在胶卷落到台面前不会读取它来显示新照片。已有成品仍可作为独立预览显示。放置期间客户端菜单本身已由原逻辑更新，附属只控制视觉展示。离开场景仍读取真实 BE 库存，不保存额外物品。

实际冲印继续围绕照片边缘进行；持有物品时优先恢复原生跟手，便于直接取放。冲印消耗不会产生取物动画，负片到成片仍由 Exposure 真实进度驱动，照片数据和成品生成不变。

**多人服务器需要同时更新本附属和依赖。** Lightroom 的场景注册在两端执行。原方块没有标准 getMenuProvider 开放入口，且客户端菜单构造需要方块坐标，因此增加一个仅针对 Lightroom 的 MenuProvider 适配器：委托原方块实体 createMenu，并通过 NeoForge 标准菜单附加数据写入原坐标。没有替换照片生成、配方、消耗或容器协议。

蹲下使用、关闭暗房场景、无法抵达工作面时，按 Cinematic 原有规则回退到 Exposure 原窗口。这是宿主的安全回退，不是正常场景显示方式。

移除台面前缘的常驻光照条、文字和对应悬停区域。悬停“冲印”或中央照片时，仍可在侧边查看“光照充足／不足”、检测亮度与 Exposure 配置要求，折射时使用原模组规定的五个采样位置。光照达标不代表材料齐全：悬停冲印目标会显示缺胶卷、相纸不适用、缺染料或成品槽阻塞等原因。状态按客户端当前已同步数据提示，冲印仍由服务端最终验证。说明文字显示在侧边，避免覆盖中央照片。

## 相机改装

- **背包/库存中右键相机：Exposure 原改装界面**，包括它原有的库存和 EMI 行为。
- **手持相机潜行 + 右键：沉浸改装界面**。由 Exposure 原本的使用流程打开，第三人称或关闭相机模块时仍回退原界面。
- 不拦截拍照操作、不改变原模组的快门/启用条件；库存右键入口仍需 Exposure 的对应服务器配置开启。

附件交互框显示实际放入的物品及数量，不再绘制机身上的黄色定位点。槽位图标、拖拽预览和点击使用同一坐标；只改变显示，不改附件数据。

相机装配采用约 60° 斜向持握及 12° 轻微抬头，镜头朝左前方，能同时看到镜头接口与机身侧面。机身、附件模型、接口轴向、握点和点击目标使用同一姿态变换。

双手平时托住机身前后两端；**右手处理胶卷和闪光灯，左手处理镜头和滤镜**，另一只手继续支撑。操作手在镜头前方或机身后方的有限空间内跟随光标，靠近可用接口时趋向对齐位置；支撑手保持握持，不随鼠标穿过机身。胶卷先移到顶部后缘上方，再向下插入；镜头/滤镜保留对准接口和旋转安装。复用原模型，没有新增可开启舱盖。取出附件直接更新原手持物，Shift 取出直接进库存，不再播放逆向拆卸动作。

相机保持固定大小，从画面下方托起；关闭时放回下方。机身及接口整体稍微移远，顶部装卷通道同步收短，手臂最大长度仍为 0.74 格。五种 GUI 高度的纯几何采样中，实际视点到机身中心约为 0.734–0.740 格，相比上一版增加约 0.024–0.095 格；这不是游戏画面测量。

选择库存物品后直接显示光标持物，不再向画面外掏取。已持有的附件从当前拳头位置送入接口；Shift/数字键安装从机身近侧边缘取件，采用短程放置。换件直接移除旧件，再安装一次新件，删除先卸后装的长时间线。安装后的空手平滑衔接当前悬停或支撑目标。

**相机安装及回手结束前不接受下一次物品操作**，覆盖工作区、抽屉、Shift、数字键与丢弃键；Esc/库存关闭、Tab 展开抽屉仍可使用。忙碌时的点击不排队，按下时被忽略的鼠标松开后也不会补放置。一次已接受的原版拖拽/触屏事务允许完整结束，避免拦截其内部归还点击。普通 Exposure 原窗口不受这一限制。

两手在跟随、装配及退出过程中保持同一组平滑控制器及速度状态。GUI 缩放只使旧接口轨迹失效，不清空手位；持续接收原同步，确认与预测一致时保留动作，真正纠正时取消道具和输入锁。掌面连续旋转修正与 Cinematic 原手臂/袖子渲染调用保持。安装道具与机身组件在实际拳头接触接口时交接；没有新增物品或操作包。用户已反馈 v0.2.11 的闪烁问题得到修复，本版保留该实现，开发环境没有进行游戏内验证。

暗房和相机分别保留台面与机身外侧的活动范围；边缘使用渐缓限制，避免光标移动把手臂无限拉长。实际附件、照片与物品操作仍由 Exposure 原菜单处理；放置期间只限制后续新输入，不缓存或重放操作。闪光灯照常显示，不为避让而隐藏。

物品栏使用 **Cinematic 原 SceneScreen 抽屉面板**：顶部快捷栏常显，鼠标移入后展开背包，移开后收起；Tab 可以固定展开，再按取消固定。相机位于抽屉下方，展开不挪动附件目标。通过局部 Mixin 调用宿主面板与命中逻辑，原有暗房及其他工作站不受此私有抽屉实例影响。未复制依赖 JAR 或纹理。

相机界面仅保留 Cinematic 抽屉作为库存显示，隐藏原版快捷栏及常规 HUD，保留聊天、字幕、调试信息等宿主也保留的辅助层。关闭后按正常界面自动恢复，不修改 hideGui 设置。

EMI 为可选兼容：只在 CameraSceneScreen 中让 EMI 使用原生空界面分支，阻止侧栏、搜索框、按钮与配方快捷键接管；普通背包、其他工作站和 EMI 全局配置不变。无需安装 EMI；已核对 EMI 1.1.22 和 1.1.24 的 NeoForge 发布 JAR 接口。胶卷热点跟随顶部后缘接口投影，保持在右侧。工作区由手部显示光标物品，不叠加同一物品的二维鼠标图标；库存抽屉、拖拽分配和触屏仍保留原图标。

实际物品图标与鼠标拖拽仍由 `AbstractContainerScreen` 处理，槽位和 Menu 均为 Exposure 原对象，不修改 Slot.x/y；适配器只转换屏幕坐标。支持普通点击、拖拽分配、Shift 快速转移、双击归集与数字键换槽；点击场景空白不会意外丢弃光标物品。第三人称打开时保留 Exposure 原窗口。

这些输入路径已接入原版实现，但尚未做游戏内鼠标/拖拽测试。相机支架不在范围内。

## 配置

`config/cinematic_exposure-client.toml`，也可用 NeoForge 配置界面：

```toml
[animations]
camera = true
lightroom = true
speed = 1.0
```

相机安装基础时长为：胶卷 0.68 秒、镜头 0.50 秒、滤镜 0.44 秒、闪光灯 0.40 秒；暗房放置为 0.36 秒，两处取出均没有额外时间线。接触阶段会短暂等候实际平滑手位到达（最多 0.45 个动画秒），实际时长可略长。时间均随动画速度配置缩放。不可达时结束视觉动作并恢复真实状态，不重发操作。

速度范围 0.25–3.0，控制附件/冲印手部动作和相机改装进出速度。暗房的走近与镜头过渡遵循 Cinematic 宿主设置。旧 `dockGui` 配置已移除。

## 构建与发布

完整 JDK 21：

```sh
./gradlew build --stacktrace
python3 tools/verify-artifact.py
```

代理云环境可用 `python3 tools/cloud-build.py build --stacktrace`，保留 TLS 校验。产物为 `build/libs/cinematic-exposure-1.21.1-neoforge-0.2.13-alpha.jar`。

GitHub Actions 支持 push、PR 和手动构建。手动启用 release 后，仅在构建与打包检查成功时发布 v0.2.13-alpha Pre-release，并上传同次构建的 JAR。不会覆盖旧版 Release。

验证脚本另运行纯 Java 几何与交互控制器检查（无 Minecraft 类或依赖在运行类路径中）：覆盖相机四种附件、已持物与近侧取件起点、短程路径连续性、可达距离、原版闪光灯间距、接触交接与收尾、GUI 高度变化后的实际距离；检查忙碌输入、迟到的松手与完整事务收尾。保留手位/速度连续性、同步确认/纠正、掌面旋转及暗房四朝向放置回归。这些检查不能替代实际渲染和输入验证。

没有启动 Minecraft 客户端或服务器。手部距离限制可能在极端 GUI 缩放、侧身或资源包模型下造成手指未完全贴合接口，需要实测微调；未宣称已解决所有穿模。需要玩家验证台面拾取范围、镜头构图、手部/物品穿模、预览与库存抽屉布局、光影及多人同步。默认皮肤/模型之外的资源包可能需要进一步调位。
